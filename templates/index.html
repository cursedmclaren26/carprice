Section 01

1. Project Overview

The Car Price Predictor is an end-to-end Machine Learning web application designed to evaluate and estimate pre-owned car market valuations with precision. In the secondary automobile market, price determination is inherently non-linear and governed by multifaceted vehicle attributes rather than simple catalog lookups. This project formulates a robust valuation model derived directly from real transaction data.

To model vehicle depreciation and price dynamics, three distinct machine learning algorithms were developed and evaluated:

Linear & Ridge Regression Establishes baseline parametric relationships and quantifies primary depreciation coefficients for age and odometer metrics.
Random Forest Regressor Non-linear ensemble bagging model combining decision trees with feature subsampling to capture subtle non-linear interactions.
XGBoost / Gradient Boosting Sequential gradient boosted regression trees minimizing residual loss to deliver optimal cross-validated predictive accuracy.

The model dynamically evaluates pricing based on key automotive parameters: brand, mileage (kilometers driven), fuel type (Petrol, Diesel, CNG, LPG, Electric), transmission (Manual vs Automatic), ownership tier, and year of manufacture.

Supervised Regression Problem Formulation

Problem Formulation: The challenge is formulated as a Supervised Machine Learning Regression problem. The ground-truth continuous target variable is "Selling Price" (in Indian Rupees ₹). Models optimize standard continuous regression objective functions (Mean Squared Error / Huber Loss) evaluated against Root Mean Squared Error ($RMSE$), Mean Absolute Error ($MAE$), and Coefficient of Determination ($R^2$).

Section 04

4. Pipeline from beginning to end (Phase 1 - Data Preprocessing)

Raw real-world automotive listings are rife with noisy tokens, missing data points, mixed units (e.g. "1248 CC", "23.4 kmpl"), and asymmetric outliers. Phase 1 transforms raw unstructured listings into an enterprise-ready feature matrix through four rigorous steps:

Missing Value Treatment

Missing entries were handled selectively based on data distribution skewness and feature cardinality:

  • Numerical Columns (e.g., Engine CC, Max Power bhp, Mileage km/l): Imputed using the Median strategy rather than the mean. Because high-performance exotic vehicles heavily skew the mean, the median provides a far more representative central tendency for standard consumer vehicles.
  • Categorical Columns (e.g., Fuel Type, Transmission, Seller Type): Imputed using the Mode (the most frequent category), stratified within each manufacturer's brand family.

Outlier Detection & Treatment

To safeguard models from extreme values (such as vintage collector listings priced at ₹1 crore+ or typographical errors like 2,500,000 km driven), the Interquartile Range (IQR) method was applied:

IQR = Q3 (75th percentile) - Q1 (25th percentile)
Lower Bound = Q1 - 1.5 × IQR
Upper Bound = Q3 + 1.5 × IQR

Outliers in columns like 'Kilometers Driven' and 'Selling Price' were capped (winsorized) at the upper statistical boundary rather than completely discarded, preserving valuable edge samples without distorting loss convergence.

Feature Engineering

To augment the predictive capacity of both linear and tree models, 4 logical domain features were engineered:

Engineered Feature Mathematical Derivation Engineering Rationale
Car_Age Current_Year (2026) - Year_Manufacture Direct temporal proxy capturing chronological vehicle depreciation over calendar time.
Annual_Km_Usage Kilometres_Driven / max(Car_Age, 1.0) Identifies excessive fleet/commercial mileage wear vs. well-maintained personal usage.
Brand_Tier Binned: [Economy, Mid-Market, Luxury] Groups manufacturers (e.g. BMW/Audi vs Maruti/Hyundai) into value-retention clusters.
Mileage_Category Classified: Low (<14), Med (14-20), High (>20 kmpl) Encodes consumer demand elasticity and market preference for fuel-efficient vehicles.

Train-Test Split

To maintain strict experimental isolation and prevent data leakage, the processed dataset was partitioned using an 80:20 Train-Test split:

  • Training Split (80%): Dedicated exclusively to training regression models and performing 5-fold cross-validation.
  • Testing Split (20%): Held-out partition strictly isolated until final model evaluation to simulate real-world generalization on unseen cars.
